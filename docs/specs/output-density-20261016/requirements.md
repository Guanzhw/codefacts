# Agent-facing output density

The user identified repeated locator labels and SHA256 fingerprints as examples
of a broader output-design problem. Audit and repair all seven workflows and
the CLI aliases rather than replacing one phrase.

- Default results should state each fact once at its useful scope: response,
  file, symbol or relationship. Prefer source locations and actionable facts
  over repeated identifiers, boilerplate and nested copies.
- Remove source fingerprints from default reading output. Keep source hashing,
  verification, index freshness and cursor validation internal. Existing
  explicit machine exports may retain their detailed contracts.
- Distinguish complete source, excerpts and omitted source clearly without
  repeating a full explanation on each result. Preserve precise locations,
  relationship direction and uncertainty, partial failures, cutoffs and usable
  continuation information.
- Keep the three default MCP entry points. Choose a coherent default reading
  format from source and real-output evidence; preserve explicit machine
  formats and document any default-contract change.
- Count saved bytes from actual before/after responses. Check that saved
  metadata space becomes available to source within the existing UTF-8 budgets.
  Do not present byte estimates as measured model-token or productivity gains.

Use an independent fresh-context output-design review and bounded real-runtime
DSH Flash audits. Preserve the immutable v0.2.1 release and earlier studies;
the presentation repair receives its own version and verification evidence.
