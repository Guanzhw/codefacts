# Markdown 输出与 token 效率验收

CodeFacts 0.1.15 为五个 MCP 工具增加 `format: "markdown"`。它沿用 compact
事实投影，把重复字段合并为表头，源码使用代码块，并仅返回一个 TextContent。
`compact` 仍为默认值；`compact` / `full` 保留 JSON 文本和 structuredContent，
供现有客户端使用。Markdown 中继续保留证据位置、共享来源哈希、关系方向、
置信度、新鲜度、截断和续页信息。`expand` 按最终渲染文本限制为 16 KiB。

## 原生响应对照

源码为 OpenSession `543e874e697523bf474f494bcf897a17f19587de`，固定 446 个文件，
关闭 LSP。两种格式使用相同候选二进制，各自新建 SQLite 状态；先调用 map
完成索引，再测量八个固定查询及两个密集 expand 的全部续页。

| 指标 | compact JSON | Markdown | 变化 |
| --- | ---: | ---: | ---: |
| 完整查询调用数（含续页） | 17 | 16 | -1 |
| TextContent UTF-8 bytes | 200,181 | 125,843 | -37.1% |
| 完整 JSON-RPC 响应 bytes | 427,392 | 129,279 | -69.8% |
| 正文静态 token 计数 | 52,416 | 37,777 | -27.9% |
| 完整响应静态 token 计数 | 107,741 | 39,666 | -63.2% |

静态 token 使用 tiktoken 的 `o200k_base` 编码器，仅作为编码代理；它不是
Luna 的实际用量。完整响应的较大降幅还包含去掉重复 structuredContent 的收益，
不能全部归因于 Markdown 语法。分页数量变化也影响累计开销；应比较完整事实覆盖，
而不是只比较首页。密集结果的 Markdown 首页可能容纳更多事实，首页 token
反而上升。空搜索的正文为 87 → 103，静态无路径为 320 → 360，说明小结果
不一定节省 token。

独立核对完整分页集合：协议缓存目标的 97 条关系、reader 目标的 188 条关系均无
缺失或新增；调用点、端点、方向、置信度和 resolution 字段一致。两段初始源码
逐字节保留，完整分页中的 38 / 31 个来源哈希一致。`ambiguous`、空结果、
`no_static_path` 的含义与限定语也保留。这是有界用例的保真证据。

## 客户端实验边界

采用两道已有真实任务的格式兼容性复验：协议缓存 revision 审查、reader 主会话
轮次顺序与子会话隔离。它不是新的独立产品投资样本，也不重开此前 36 次对照。

- 客户端为 Codex CLI `0.155.0-alpha.9.2`，评测 agent 为 `gpt-5.6-luna / medium`。
- 每题各运行 compact / Markdown 一次，顺序为缓存 compact → 缓存 Markdown →
  轮次 Markdown → 轮次 compact。最多一次 readiness，每次最多 240 秒。
- 两组提示相同；透明代理改变 schema 的格式默认值，并在实际调用省略 format 时
  补入对应值。保留原始请求、实际转发请求和原样响应，审核真实工具使用。
- 首先 expand 指定目标，存在 callees 续页时读取下一页；MCP 和 shell 合计最多
  16 次。答案要求来源哈希、调用方向、置信度和未读取续页说明。
- 冻结每题四项业务正确性标准；评分时隐藏格式映射及成本，主审另查协议门槛。
  两边均达到 4/4 且通过门槛，才解释该配对的 token 差异。
- 环境、源文件或二进制哈希、传输、策略、用量归并失败后停止尚未派发的运行。
  不修改提示，不替换失败运行；所有开始的运行均计费。

候选二进制 SHA-256：
`8086fe0ca13fa2511bbde86c52ba78b92a5f19dace2192c0b8bbe328231df487`。
源码清单 SHA-256：
`f622b8597df69ab3a92d04489e89ad12601525f962df88938bb65d7905ec9db9`。
完整本地材料保存在 `target/markdown-acceptance-20260920/`，包括 `freeze.json`、
提示、评分标准、原生原样响应、透明代理日志和客户端运行记录。原始会话留在
忽略目录；公开报告与汇总只保留可复查的必要结果。

## 实际 Luna 结果与决定

四次运行均完成；实际 MCP 使用、转发格式、最终成功的精确续页、目标文件完整
哈希及只读范围均已核对，用量与原始 rollout 一致，冻结输入在结束后仍完全一致。
全部失败调用也计入提供方用量。

| 任务 / 格式 | 严格完整性得分 | total tokens | cached input | 非缓存输入 | output（含 reasoning） | 耗时 | MCP / shell |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 缓存 / compact | 1/4 | 406,262 | 338,688 | 64,232 | 3,342（1,045） | 119.81 s | 2 / 6 |
| 缓存 / Markdown | 2/4 | 271,970 | 196,096 | 72,862 | 3,012（1,111） | 87.49 s | 5 / 3 |
| 轮次 / Markdown | 3/4 | 286,711 | 240,128 | 43,849 | 2,734（685） | 89.88 s | 3 / 7 |
| 轮次 / compact | 0/4 | 285,904 | 237,056 | 46,167 | 2,681（865） | 116.50 s | 4 / 3 |

评分采用冻结的四项复合标准，每项要求全部子条件才得分。上述分数衡量严格的
答案完整性，**不是事实正确率**：四份答案的主要结论均正确，即现有 provider
revision 已支持缓存失效、reader 不应按 timestamp 排序。失分主要来自遗漏：
缓存的前置检查和命中后 touchCache、Map 声明位置、明确的渲染函数名称、完整的
测试断言等。0/4 的轮次答案也正确说明了主会话过滤、源顺序及 Set 接收者。
原始独立评分不因成本数据而调整；详见
[评分标准](../benchmarks/agent-eval/markdown-rubric.md)和
[答案及完整汇总](../benchmarks/agent-eval/markdown-results.json)。

没有一对达到双方 4/4，因此没有通过质量门槛的端到端节省结论。仅记录观察值：
缓存任务 Markdown total 低 33.1%，但非缓存输入加输出高 12.3%；轮次任务 total
高 0.3%，非缓存输入加输出低 4.6%。两题耗时分别低 27.0% / 22.9%。每格只有一次，
不能据此推出普遍收益或质量提升。

| 任务 / 格式 | MCP 正文 bytes（含错误） | MCP 响应 bytes（含错误） | shell 原始输出 bytes | 客户端 wrapper 输出 bytes | MCP 参数错误 / wrapper 语法错误 / shell 非零退出 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 缓存 / compact | 32,115 | 68,336 | 60,569 | 102,112 | 0 / 3 / 0 |
| 缓存 / Markdown | 40,829 | 41,689 | 122,756 | 133,353 | 2 / 1 / 0 |
| 轮次 / Markdown | 23,549 | 24,112 | 124,817 | 126,307 | 1 / 1 / 1 |
| 轮次 / compact | 31,632 | 67,150 | 43,682 | 120,010 | 2 / 1 / 0 |

两种格式都出现了模型抄写长游标失败；收到显式错误后，全部最终读取了正确续页。
缓存 Markdown 还重新请求首页并用正则提取游标。这提供了后续缩短或改善游标消费
方式的真实线索，但不证明 Markdown 导致抄写错误。缓存 Markdown 答案将 caller/
callee 称为 confirmed，而关系证据实际为 static、端点证据为 confirmed；这项
标签归属问题也保留在记录中。其调用方向和对启发式候选的区分正确。

客户端有时只投影 TextContent，有时打印完整工具结果；源码读取范围和语法重试也
不同。因此原生完整响应减少 63.2%，不能直接换算为模型输入减少 63.2%。本轮同样
没有固定每次查询返回的事实数量：不同格式的 16 KiB 分页边界不同。

正式四次共 **1,250,847 tokens**；唯一一次客户端 readiness 为 **94,872 tokens**、
60.98 秒、3 次 MCP（含 1 次错误游标重试），合计 **1,345,719 tokens**。readiness
仅确认传输及续页可用，其答案缩写了哈希，未作为正式质量样本。实现、原生检查、
审查和打包的工程准备 token 未汇总，不能将这项开销算作零。

**决定：发布可选 Markdown，保留 compact JSON 默认值。** 原生输出压缩和事实
保留已验证；尚无证据承诺更低的整项任务成本。保持本轮四次记录封闭，不替换
失败项，也不为了达到节省数字继续调提示。后续优先处理已复现的游标使用成本，
需要单独冻结验证；扩大格式默认值的使用范围仍须通过任务效果门槛。

## 实现验证

774 项 Rust 测试、23 项 npm 测试、格式检查和 clippy 通过。npm 测试实际安装
打包后的 launcher 和平台包，检查服务器版本并调用 Markdown 搜索。新增分页
用例逐页验证 80 个调用点无遗漏，且每页实际 Markdown 文本不超过 16 KiB。

独立审查发现并修复两处表示问题：边界反引号导致名称被误读，以及单条关系的
深层标题丢失证据归属。修复后使用实际 stdio 结果复查，确认名称、表格中的管道符、
`evidence.*` 和 `from.evidence.*` 均保留正确含义，旧版和新版 MCP 协议均兼容。

[跨平台 CI](https://github.com/Guanzhw/codefacts/actions/runs/35519464105)
六项全部通过，包括 Windows、macOS、Linux、Node 18、Rust MSRV 和格式/lint。
